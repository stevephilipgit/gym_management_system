================================================================================
                    GYM PROJECT - DATABASE SCHEMA
                  Complete Field Documentation
================================================================================

DATABASE: MongoDB (Mongoose)

================================================================================
1. ADMIN COLLECTION
================================================================================
Collection Name: admins
Purpose: Admin user authentication and authorization

Fields:
-------
_id                  (ObjectId)      - MongoDB auto-generated ID
fullName             (String)        - Full name of admin (required, trimmed)
username             (String)        - Unique username (required, trimmed, unique)
email                (String)        - Unique email (required, trimmed, lowercase, unique)
role                 (String)        - Role type (required, enum: "superadmin", "trainer", "finance")
                                       Default: "trainer"
passwordHash         (String)        - Hashed password (required)
lastLogin            (Date)          - Last login timestamp (default: null)
resetOtp             (String)        - OTP for password reset (default: null)
otpExpiry            (Number)        - OTP expiry time in milliseconds (default: null)
createdAt            (Date)          - Auto-generated timestamp
updatedAt            (Date)          - Auto-generated timestamp

Indexes:
  - username (unique)
  - email (unique)

Used in:
  - Login form
  - Admin authentication

================================================================================
2. MEMBER COLLECTION
================================================================================
Collection Name: members
Purpose: Store gym member information and membership details

Fields:
-------
_id                  (ObjectId)      - MongoDB auto-generated ID
gymId                (Number)        - Unique member ID (required, unique)
fullName             (String)        - Member full name (required)
                                       NOTE: Formatted with father name by pre-save hook
fatherName           (String)        - Father's name (required)
dob                  (Date)          - Date of birth (required)
bloodGroup           (String)        - Blood group (required)
gender               (String)        - Gender (required, enum: "Male", "Female")
medicalIssues        (String)        - Medical issues (default: "None")
address              (String)        - Residential address (required)
aadhar               (String)        - Aadhar number (required, unique, 12 digits only)
                                       Auto-stripped of non-digits, validated for 12 digits
occupation           (String)        - Member's occupation (required)
phone                (String)        - Phone number (required, 10 digits, starts with 6-9)
                                       Format: /^[6-9]\d{9}$/
photoUrl             (String)        - Profile photo URL (optional)
gymPlan              (String)        - Package/plan selected (required)
                                       Possible values: "1 Month", "3 Months", "6 Months", "12 Months"
trainingType         (String)        - Type of training (required)
                                       Enum: "Weight Loss", "Weight Gain", "Transformation"
paymentStatus        (String)        - Payment status (enum: "paid", "not_paid", default: "not_paid")
paymentMode          (String)        - Payment method (enum: "cash", "gpay", "card", default: null)
currentPaymentDate   (Date)          - Current payment date
oldPaymentDate       (Date)          - Previous payment date
validityEnd          (Date)          - Membership validity end date
status               (String)        - Membership status (enum: "active", "expired", "draft", default: "draft")
customFields         (Object)        - Dynamic custom fields (default: {})
                                       Stores additional information from DynamicField collection
createdAt            (Date)          - Auto-generated timestamp
updatedAt            (Date)          - Auto-generated timestamp

Indexes:
  - gymId (unique)
  - aadhar (unique)

Used in:
  - Member registration form
  - Member update form
  - Member dues/billing

================================================================================
3. PACKAGE COLLECTION
================================================================================
Collection Name: packages
Purpose: Store gym package/membership plans with pricing

Fields:
-------
_id                  (ObjectId)      - MongoDB auto-generated ID
name                 (String)        - Package name (required)
                                       Examples: "1 Month", "3 Months", "6 Months", "12 Months"
months               (Number)        - Duration in months (required)
priceWeightLoss      (Number)        - Price for Weight Loss training (required)
priceWeightGain      (Number)        - Price for Weight Gain training (required)
priceTransformation  (Number)        - Price for Transformation training (required)
createdAt            (Date)          - Auto-generated timestamp
updatedAt            (Date)          - Auto-generated timestamp

Indexes:
  - name (recommended for fast lookups)

Used in:
  - Admin manage packages page
  - Member package selection
  - Bill calculation

================================================================================
4. PAYMENT LOG COLLECTION
================================================================================
Collection Name: paymentlogs
Purpose: Track individual payment transactions

Fields:
-------
_id                  (ObjectId)      - MongoDB auto-generated ID
gymId                (Number)        - Member's gym ID (required)
name                 (String)        - Member's name (required)
plan                 (String)        - Package plan (required)
                                       Examples: "1 Month", "3 Months", "6 Months", "1 Year"
trainingType         (String)        - Type of training (required)
                                       Enum: "Weight Loss", "Weight Gain", "Transformation"
amount               (Number)        - Payment amount (required)
type                 (String)        - Transaction type (required, enum: "new", "renewal")
paymentMode          (String)        - Payment method (required, enum: "cash", "gpay", "card")
paidAt               (Date)          - Payment timestamp (default: Date.now)
createdAt            (Date)          - Auto-generated timestamp
updatedAt            (Date)          - Auto-generated timestamp

Indexes:
  - gymId (recommended for member payment history)
  - paidAt (recommended for payment reports)

Used in:
  - Payment processing
  - Bill generation
  - Member payment history

================================================================================
5. FINANCE LOG COLLECTION
================================================================================
Collection Name: financelogs
Purpose: Track financial records for reporting and analytics

Fields:
-------
_id                  (ObjectId)      - MongoDB auto-generated ID
gymId                (Number)        - Member's gym ID (required, indexed)
memberName           (String)        - Member's name (required, trimmed)
amount               (Number)        - Transaction amount (required, min: 0)
plan                 (String)        - Package plan (required, indexed)
                                       Enum: "1 Month", "3 Months", "6 Months", "12 Months"
                                       NOTE: Store normalized labels only
trainingType         (String)        - Type of training (required, indexed)
                                       Enum: "Weight Loss", "Weight Gain", "Transformation"
                                       NOTE: Must use space in "Weight Loss" etc (used by charts)
type                 (String)        - Transaction type (required, indexed)
                                       Enum: "new", "renew"
date                 (Date)          - Transaction date (required, indexed, default: Date.now)
createdAt            (Date)          - Auto-generated timestamp
updatedAt            (Date)          - Auto-generated timestamp

Indexes:
  - gymId
  - plan
  - trainingType
  - type
  - date

Used in:
  - Finance reports
  - Dashboard analytics
  - Revenue tracking

================================================================================
6. DYNAMIC FIELD COLLECTION
================================================================================
Collection Name: dynamicfields
Purpose: Store custom fields that can be added to member registration

Fields:
-------
_id                  (ObjectId)      - MongoDB auto-generated ID
key                  (String)        - Unique field key (required, unique, lowercase, trimmed)
label                (String)        - Field label for display (required, trimmed)
type                 (String)        - Field data type (required)
                                       Enum: "text", "number", "date", "dropdown"
required             (Boolean)       - Is field mandatory? (default: false)
options              (Array[String]) - Options for dropdown type (default: [])
                                       Validation: Required if type is "dropdown"
createdAt            (Date)          - Auto-generated timestamp
updatedAt            (Date)          - Auto-generated timestamp

Indexes:
  - key (unique)

Used in:
  - Manage fields admin page
  - Dynamic member registration fields
  - Member profile customization

================================================================================
FORM FLOWS & REQUIRED FIELDS
================================================================================

LOGIN FORM
----------
Admin Login:
  - username (from Admin collection)
  - email (from Admin collection)
  - password (hashed as passwordHash in Admin collection)

MEMBER REGISTRATION FORM (From Login till Bill)
-----------------------------------------------
Step 1 - Basic Information:
  - fullName
  - fatherName
  - dob
  - gender
  - bloodGroup
  - phone
  - aadhar

Step 2 - Address & Occupation:
  - address
  - occupation
  - medicalIssues

Step 3 - Photo Upload:
  - photoUrl

Step 4 - Membership Details:
  - gymPlan (package selection from Package collection)
  - trainingType (Weight Loss / Weight Gain / Transformation)
  - paymentMode (cash, gpay, card)

Step 5 - Custom Fields (Dynamic):
  - customFields (populated from DynamicField collection)

MEMBER UPDATE FORM
------------------
All fields from registration can be updated

PAYMENT/BILL FORM
-----------------
Required for generating bills:
  - Member Data (from Member collection)
    - gymId
    - fullName
    - gymPlan
    - trainingType
  - Package Data (from Package collection)
    - appropriate price based on trainingType
  - Payment Data (to create PaymentLog)
    - amount
    - paymentMode
    - type (new/renewal)
  - Finance Log Entry
    - gymId
    - memberName
    - amount
    - plan
    - trainingType
    - type (new/renew)

ADMIN MEMBER MANAGEMENT
-----------------------
List/View Members:
  - All Member fields

Create Member:
  - All Member fields

Update Member:
  - All Member fields

Dues Management:
  - gymId
  - currentPaymentDate
  - validityEnd
  - paymentStatus
  - status

================================================================================
RELATIONSHIPS & CONNECTIONS
================================================================================

Admin → Member Management
  Admin (role-based) manages Members via routes

Member ← Package
  Member selects a Package (via gymPlan field stores package name)
  Price lookup: Package.price{trainingType}

Member → PaymentLog
  Creating/renewing member creates PaymentLog entry
  Connection: gymId in both collections

Member → FinanceLog
  Payment creates FinanceLog entry
  Connection: gymId, memberName in both collections

Member → DynamicField
  Member.customFields stores values for DynamicField keys
  Connection: DynamicField.key matches customFields object keys

PaymentLog ← FinanceLog
  Both track same transaction
  PaymentLog has more detail (paidAt time)
  FinanceLog used for reporting

================================================================================
DATA VALIDATION RULES
================================================================================

MEMBER COLLECTION:
  - aadhar: Must be 12 digits (auto-stripped of non-digits)
  - phone: Must be 10 digits starting with 6-9
  - gender: Must be "Male" or "Female"
  - status: "active", "expired", or "draft"
  - paymentStatus: "paid" or "not_paid"
  - trainingType: "Weight Loss", "Weight Gain", or "Transformation"
  - gymPlan: Examples - "1 Month", "3 Months", "6 Months", "12 Months"

ADMIN COLLECTION:
  - role: "superadmin", "trainer", or "finance"
  - email: Must be lowercase, unique
  - username: Must be unique

FINANCE LOG COLLECTION:
  - plan: "1 Month", "3 Months", "6 Months", "12 Months" (normalized only)
  - trainingType: Must include space ("Weight Loss", not "WeightLoss")
  - type: "new" or "renew"
  - amount: Must be >= 0

PAYMENT LOG COLLECTION:
  - type: "new" or "renewal"
  - paymentMode: "cash", "gpay", or "card"
