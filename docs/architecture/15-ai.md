# 15 — AI Assistant

## Access control

- Mounted as `/api/ai` with `adminAuth, requireRole("superadmin")` (server.js:155).
- Frontend route `/admin/ai-assistant` wrapped in RoleGuard superadmin
  (App.jsx:66); sidebar item superadmin-only.
- **AI cannot be reached by trainers/finance.** It can only be used by
  superadmin, so AI data reads are not gender-scoped (they are all-gender) —
  acceptable given the superadmin-only gate, but worth noting that the AI tools
  themselves never apply `req.admin.scope`.

## Provider / model / key handling

- `services/ai/aiClient.js`: Google Gemini via `@google/generative-ai`.
- `GEMINI_MODEL` env (default `gemini-1.5-flash`), `GEMINI_API_KEY` env,
  `AI_ENABLED` env (`"true"` to enable). If disabled or missing key → model is
  null → falls back to rule-based responses. Single retry with 1s sleep.
- 10-second timeout per Gemini call.

## Routes (routes/aiRoutes.js)

- `POST /chat` — `aiStrictLimiter` (100/15min) + `aiRequestLimiter` (20/min) →
  `chatService.processMessage(message, sessionId)`.
- `POST /confirm` — same limiters → `agentRunner.executeConfirmed(token)` or
  `cancelPending`.
- Session ID comes from `x-session-id` header; a new UUID is minted if absent.

## Tools (services/ai/toolSchemas.js + tools.js)

| Tool | Params | Side effect | Confirmation |
|------|--------|-------------|--------------|
| `getTotalMembers` | — | no | no |
| `getExpiringMembers` | days 1-90 | no | no |
| `sendReminder` | members[] | yes (prepares WhatsApp links) | ✅ requires confirmation |

Tools query the `Member` collection directly (`getTotalMembers` counts all;
`getExpiringMembers` selects name/phone/validityEnd sorted by validityEnd). They
do **not** filter by status or gender.

## Conversation / memory

- `conversationStore.js`: in-memory `Map`, max 10 message pairs per session,
  session TTL 30 min, cleanup every 5 min (unref'd interval).
- `aiCache.js`: in-memory response cache, TTL 2 min, max 100 entries.
- `pendingActionStore.js`: confirmation tokens, TTL 5 min, max 50, cleanup every
  2 min.
- **All in-process memory** — no Redis, no persistence. Lost on restart. Not
  distributed-safe.

## Prompt injection defenses

- `chatService.js:18-25` — blocks messages matching patterns like "ignore
  previous instructions", "system prompt", "forget your", "act as" → returns
  "I can only help with gym-related queries."
- Output JSON is parsed and only **registered tools** may be executed
  (`isValidTool`); unknown tools are rejected with a warning (chatService.js:221-226).
- `sendReminder` is chained only from `getExpiringMembers` results
  (agentRunner.js:16-28); it never sends messages — it returns WhatsApp links.
- Max 5 steps per agent run; per-step 8s timeout.

## Dangerous actions / auditability

- The only side-effect tool `sendReminder` produces `wa.me` links — **it does not
  send anything** (reminderService.prepareRemindersWithMessages). The
  `jobs/reminderAgent.js` cron is `enabled: false`.
- There is no audit log for AI chat/tool actions. Gemini calls themselves are
  not logged (only errors). **Auditability gap.**

## If AI is unavailable

- `processMessage` catches Gemini errors and falls back to rule-based answers
  (total-count / expiring-members phrases). The route returns 500 only on
  unexpected errors, 502 for `[ToolExecutor]` failures, 400 for length/empty.
